# RepoBloom demo script

Target length: 2 minutes 40 seconds.

## 0:00–0:20 — Problem

“Developers have unlimited tutorials but still struggle to decide what to learn next. Most roadmaps begin with a self-reported quiz and end with another throwaway project. RepoBloom starts with evidence: the work already visible in your GitHub.”

Show the landing page and skill constellation.

## 0:20–0:48 — Analyze a real profile

“I enter my public GitHub username. No login is required, and RepoBloom never asks for private repository access.”

Click **Map my growth**.

“RepoBloom reads repository languages, descriptions, topics, recency, and project context. It turns those signals into a skill map and keeps links to every repository behind the recommendation.”

Hover two skill nodes, then scroll to the evidence ledger.

## 0:48–1:15 — Put the learner in control

“The system proposes the next capability that would make my existing work more complete, but it does not make the choice for me. I can change both the focus and the repository I want to improve.”

Change the **Focus to strengthen** and **Project to improve** controls.

“This creates a clear learning contract: one capability, one real project, four weeks, and evidence I can defend.”

## 1:15–1:55 — Complete a proof sprint

Open Weeks 1 through 4 and mark two proof items complete.

“Each week has a measurable outcome, three artifacts to ship, and a proof condition. The bloom grows only when I produce evidence such as a test, benchmark, diff, explanation, or demo. Learning progress becomes visible work—not a passive course checkbox.”

Show the progress percentage and growing bloom.

## 1:55–2:20 — Codex as a learning partner

Click **Copy Codex kickoff**.

“RepoBloom generates a bounded Codex kickoff prompt with the project, focus, and proof requirements. Codex is asked to inspect first, ask me to predict outcomes, work in small steps, and verify the result. It supports judgment instead of replacing it.”

Click **Download sprint**.

“The full sprint is portable Markdown, so I can use it in my repository, share it with a mentor, or keep it as an auditable learning record.”

## 2:20–2:34 — Product architecture

“The deterministic engine owns observed facts. GPT-5.6 receives only that bounded evidence through the Responses API and returns a structured plan. A strict JSON schema prevents incomplete output and the prompt forbids unsupported skill claims. If the model or GitHub is unavailable, the product degrades gracefully.”

## 2:34–2:40 — Close

“RepoBloom turns repository history into the next proof of growth. Grow from what you have already built.”

End on the bloom and final call-to-action.

## Recording checklist

- Use 1080p and enlarge browser text if needed.
- Keep cursor movements slow and deliberate.
- Use a profile with clear repositories and a visually interesting skill map.
- Reset local proof progress before recording.
- Keep the final edit below three minutes.
- Show the working product, not presentation slides.
- Say both “Codex” and “GPT-5.6” in the audio.
